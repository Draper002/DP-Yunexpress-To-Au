# 网页版本开发进度

更新时间：`2026-07-30 21:35 CST (Asia/Shanghai)`

## 当前状态

Web 版已完成云途和顺丰国际三步工作流，并已部署到 `https://dpz.zylgzx.cn`。业务逻辑统一来自 `shared/fulfillment/`，Windows、Mac 和 Web 不维护重复字段映射。

## 已完成

- FastAPI 后端与响应式工作台，支持云途/顺丰国际逐步骤切换。
- 管理员与员工账号；管理员创建员工并维护固定配置。
- 每个员工只显示自己的处理记录，也不能下载其他员工的结果。
- 固定配置支持 SKU 商品库、云途标准模板、顺丰国际标准模板和 DP 发货模板。
- 固定配置可以单独替换一份，无需重复提交其他模板。
- 云途第 1 步：DP CSV 生成云途批量寄件 Excel。
- 云途第 2 步：云途订单信息生成 DP 发货回填模板。
- 云途第 3 步：面单 ZIP 按 SKU 整理，并返回供应商总压缩包。
- 顺丰第 1 步：DP CSV 生成顺丰 XLSM，业务类型和是否带电由用户明确选择。
- 顺丰第 2 步：顺丰 `.xls/.xlsx` 生成 DP 回填模板，承运商固定为 `SF INTERNATIONAL`。
- 两个平台第 2 步自动复用第 1 步 DP CSV，并严格核对 `processing` 订单集合；错批次时停止生成。
- 顺丰第 3 步：自动复用第 2 步订单数据，要求运单集合与合并面单 PDF 完全一致，再按“寄方姓名”拆分并返回总压缩包。
- 第 1 步默认启用“相同收件人 + 相同 SKU”合单，允许用户取消；合单计划绑定原始 CSV 哈希、日期和承运平台。
- 第 2 步自动复用合单计划，把同一真实运单号回填到组内全部 DP 订单，并下载合并订单与运单对应表。
- 云途和顺丰第 3 步均将合并面单从普通供应商分组中移除，生成独立合并件说明和供应商 ZIP。
- 两个平台使用独立批次目录，避免用户切换平台后误用上一批文件。
- 脚本执行增加进程内互斥锁，避免并发请求修改共享命令参数。
- 耗时脚本在线程池执行，并通过单进程任务锁保护批次文件和固定配置；处理期间登录与健康检查仍可响应。
- 第 1、2 步仅在脚本成功后提交新的批次文件；失败上传会删除，不污染后续步骤。
- 固定配置先完成文件类型和模板字段校验，再统一替换；任一文件错误时原配置保持不变。
- 浏览器按用户电脑本地时区填写默认日期；启动时清理过期会话。
- 提供 `/healthz`、Docker 非 root 用户和 Compose 健康检查。
- 项目根目录 `.dockerignore` 已覆盖真实业务文件、构建目录和本地数据。

## 批次与数据规则

- 批次文件位于 `data/working/<user_id>/<platform>/`。
- 结果位于 `data/results/<user_id>/<date>/<platform>/`。
- 第 3 步成功后清理对应平台的批次文件；第 1、2 步失败输入会删除，同时保留上一份已验证批次。
- SQLite、固定配置和结果目录必须挂载到持久化磁盘并纳入备份。
- Web 单文件上传上限为 80 MB；反向代理建议允许 100 MB，并设置至少 300 秒超时。

## 上线前仍需处理

- 必须启用 HTTPS，并保持 `DP_WEB_COOKIE_SECURE=1`。
- 增加登录限流、CSRF 防护、密码重置、员工停用和安全审计。
- 增加失败批次及历史结果的自动过期清理。
- 高并发使用场景应改用后台任务队列、PostgreSQL 和私有对象存储。
- 当前部署按单个 Uvicorn 进程设计，不要自行增加 `--workers`；跨进程锁和共享任务队列尚未实现。
- 首次服务器部署先使用脱敏文件小批量验收，再处理真实订单。
