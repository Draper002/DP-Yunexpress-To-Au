## 已完成

### 业务流程

- 第 1 步：DP 订单 CSV 转云途批量寄件模板。
- 第 2 步：云途或顺丰国际订单信息转 DP 发货回填模板。
- 第 2 步自动复用第 1 步 DP CSV，只比较 `processing` 订单，并要求承运商订单号集合完全一致；用户无需重复选择 DP CSV。
- 第 3 步：云途要求 DP、云途订单和面单集合完全一致后按 SKU 分拣；顺丰要求第 2 步运单与 PDF 面单完全一致后按寄方姓名拆分。
- 第 1 步可合并收件人六项标准化信息及 SKU 均一致的订单，并生成带原始 CSV 哈希、日期和平台校验的合单计划。
- 第 2 步把一个承运商包裹的运单号展开到组内全部原始 DP 订单；计划之外的重复运单继续拒绝。
- 第 3 步将合并件从普通 SKU/寄方分组中移除，单独输出一张面单、合并订单说明和供应商 ZIP。
- SKU 文件夹命名：`日期+SKU+申报中文名+数量`。
- 每个 SKU 文件夹同时包含 PDF 和供应商 ZIP。
- 单个 SKU 文件夹不放发货明细表。
- 操作结果按发货日期保存。

## 当前已知限制

- Windows、Mac 和 Web 的入口已经分开，业务脚本统一位于 `shared/fulfillment/`。
- 多个脚本各自定义输出路径，尚未抽取为共享模块。
- Mac 固定配置路径沿用桌面版自动识别逻辑，尚未在 Mac 实机验证持久化体验。
- Tkinter 可以实现接近 OS 26 的配色和层级，但无法实现完整原生液态玻璃效果。
- 没有 Apple Developer 账户，因此当前 Mac 版本只能先做本机测试和临时签名。
- Web 将耗时处理放入后台线程，但为保护共享脚本参数仍采用单进程串行任务队列，适合低并发；高并发需要独立任务队列、PostgreSQL 和对象存储。
- Web 尚未实现登录限流、CSRF 令牌、密码重置、自动过期清理和完整安全审计。
- DP 一个订单包含多个 SKU 时仍会明确拒绝自动处理，需要先确定拆包和供应商归属规则。
- 合单 V1 只处理同一收件人与同一 SKU，不跨 SKU、跨供应商或跨承运平台合并。
- “多个 DP 订单使用同一运单号”的输出逻辑和防错校验已完成，但仍需用户用小批量真实订单确认 DP 后台接受该回填方式。
- 当前 Windows 环境没有 Docker，部署包已做静态与应用级验证，但 Docker 镜像仍需在 Linux 服务器实际构建。
